# Практическая работа № 3

Проект на Java 17 и Maven по дисциплине «Тестирование и контроль качества ПО».

- **Часть 1.** Модульные тесты для сервиса обработки заказов и подсчёта простых чисел с JUnit 5 и Mockito. Исходные материалы задания находятся в `attahments/`.
- **Часть 2.** REST API для учёта подписок. Пользователь управляет своими подписками, вручную регистрирует фактические платежи и получает отчёт о расходах за период. Сервер использует Spring Boot, Spring Security, Spring Data JPA, Hibernate и файловую H2.

[Отчёт по работе](./Отчёт_3_Рачеев.docx) · [Контракт OpenAPI](./src/main/resources/static/openapi.json)

## Требования из практической работы № 2

### Функциональные требования

| № | Требование |
|---|---|
| F1 | Регистрация по email и паролю. Email уникален без учёта регистра, пароль занимает от 8 до 72 байт в UTF-8. Успешная регистрация возвращает `201`, повторный email — `409`, некорректные данные — `400`. |
| F2 | При входе сервис выдаёт Bearer-токен на один час. Выход отзывает предъявленный токен и возвращает `204`. Неверные данные для входа, отсутствующий, просроченный или отозванный токен дают `401`. |
| F3 | Владелец может создавать подписки, просматривать список и отдельные записи, полностью обновлять и удалять их. Подписка содержит название, категорию, сумму, периодичность, дату следующего платежа и статус. Чужая или отсутствующая подписка даёт `404`. |
| F4 | Пользователь может записать фактический платёж по существующей подписке, которой владеет, и получить историю за период. Сумма положительная и указывается с точностью до копеек. Дата платежа не позже текущей даты UTC. |
| F5 | Отчёт содержит итоговую сумму в RUB, количество платежей и суммы по категориям. Период включает обе границы и занимает от 1 до 366 дней. Для пустой истории итог равен нулю. Некорректный диапазон даёт `400`. |

### Требования к качеству и надёжности

| № | Требование |
|---|---|
| N1 | Пароли хранятся в виде хешей BCrypt, токены — в виде хешей SHA-256. Пароли и токены не записываются в журналы. Владелец определяется по токену, его права проверяются при работе с подписками и платежами. |
| N2 | Подтверждённые операции сохраняются в файловой H2 и доступны после перезапуска. Для сумм используются `DECIMAL` с двумя знаками после запятой и `BigDecimal` в Java. |
| N3 | При записи платежа сохраняются название и категория подписки. Изменение или удаление подписки сохраняет историю и итог прежних отчётов. Новый платёж по удалённой подписке невозможен. |
| N4 | Проект собирается Maven на Java 17, ключевые сценарии API проверяются локально. Требуемое покрытие бизнес-логики — не менее 80% ветвей, 90% строк и 90% инструкций. |

### Критерии приёмки

- Повторная регистрация с тем же email в другом регистре возвращает `409`. Запрос со старым токеном после выхода возвращает `401`.
- Попытка прочитать чужую подписку или записать платёж по ней возвращает `404`.
- Два платежа на 19,90 и 5,20 ₽ на границах периода дают итог 25,10 ₽. После удаления подписки и перезапуска отчёт по тому же периоду сохраняет результат.

## Запуск и тесты

Требуются JDK 17 и Maven. Выполняйте команды из корня проекта.

```powershell
mvn clean verify
mvn spring-boot:run
```

Для запуска с демонстрационными данными используйте профиль `demo`.

```powershell
mvn spring-boot:run "-Dspring-boot.run.profiles=demo"
```

Демо-аккаунты `demo@example.test` и `demo-other@example.test` используют пароль `Lab3-demo-2026!`. У первого аккаунта три подписки и четыре платежа, у второго — одна подписка и один платёж. База хранится в `data/`. Повторный запуск профиля сохраняет существующие записи без дублирования.

## Документация API

После запуска откройте [Swagger UI](http://127.0.0.1:8080/swagger-ui.html) или загрузите [OpenAPI JSON](http://127.0.0.1:8080/openapi.json).

1. Вызовите `POST /api/auth/login` с email и паролем демо-аккаунта.
2. Скопируйте `accessToken` из ответа и вставьте его в поле **Authorize** в Swagger UI.
3. Вызовите `GET /api/subscriptions` или запросите отчёт через `GET /api/analytics/expenses`. Для HTTP-клиента передавайте заголовок `Authorization: Bearer <accessToken>`.

| Метод и путь | Назначение |
|---|---|
| `POST /api/auth/register` | Создать аккаунт |
| `POST /api/auth/login` | Получить токен |
| `POST /api/auth/logout` | Отозвать текущий токен |
| `GET /api/subscriptions` | Получить список подписок |
| `POST /api/subscriptions` | Создать подписку |
| `GET /api/subscriptions/{id}` | Получить подписку |
| `PUT /api/subscriptions/{id}` | Полностью обновить подписку |
| `DELETE /api/subscriptions/{id}` | Удалить подписку |
| `POST /api/payments` | Записать фактический платёж |
| `GET /api/payments?from=…&to=…` | Получить историю платежей |
| `GET /api/analytics/expenses?from=…&to=…` | Получить сумму, количество и разбивку расходов по категориям |

Даты в JSON и параметрах `from` и `to` передаются в формате `YYYY-MM-DD`. Все маршруты API, кроме регистрации и входа, требуют Bearer-токен.

Пример тела для `POST /api/subscriptions`.

```json
{
  "name": "Music Plus",
  "category": "MEDIA",
  "amount": 299.00,
  "billingPeriod": "MONTHLY",
  "nextChargeDate": "2027-01-15",
  "status": "ACTIVE"
}
```

Для `POST /api/payments` передайте `subscriptionId` из ответа о создании подписки, фактически уплаченную сумму в поле `amount` и дату платежа в `paidOn`. Полный перечень схем и кодов ответа приведён в контракте OpenAPI.
